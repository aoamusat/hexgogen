# {{PROJECT_NAME}}

A Go API generated by Hexgogen using hexagonal architecture, Gin,
PostgreSQL/GORM, Zerolog, and PASETO v2 local tokens.

## Run locally

Install Go 1.25.6 or newer, Make, and Docker with Compose (or use an existing
PostgreSQL database):

```sh
cp .env.example .env
make db-up
make tools
export DATABASE_URL='postgres://postgres:postgres@localhost:5432/hexgogen?sslmode=disable'
make migrate-up
make run
```

Edit `.env` for your environment. With an existing PostgreSQL server, create a
database and skip `make db-up`. Migration commands read exported environment
variables and do not load `.env`; the application loads `.env` in development.
Use `make db-down` to stop the local database; its named volume is preserved.

The sample user endpoints are public. Add authentication and authorization for
application-specific access rules before storing private data.

## Example API

| Method | Path | Result |
| --- | --- | --- |
| POST | `/v1/users` | Create a user from `{"name":"Ada"}` |
| GET | `/v1/users/:id` | Fetch a user by UUID |
| GET | `/healthz` | Process liveness; no database query |
| GET | `/readyz` | Database readiness with a short timeout |

```sh
curl -i -X POST localhost:8000/v1/users \
  -H 'Content-Type: application/json' -d '{"name":"Ada"}'
# Use the Location header or data.id from the response:
curl localhost:8000/v1/users/REPLACE_WITH_USER_UUID
```

Successful responses use `{"data": ...}`. Errors use
`{"error":{"code":"not_found","message":"resource not found","request_id":"..."}}`.
Validation errors include a `fields` map and return 400; malformed JSON and unknown
JSON fields are rejected. Unsupported content types return 415, oversized bodies
413, missing users/routes 404, unsupported methods 405, unavailable readiness 503,
and unexpected errors 500. Internal error details appear only in logs.
`POST /v1/users` returns 201 and a Location header. Names are trimmed and must
contain 1–100 characters. Duplicate names are allowed; user IDs are unique.

## Structure

```text
cmd/server/           Application entry point and process signal handling
configs/              Environment loading and validation
api/                  HTTP server, routes, middleware, and v1 handlers
domain/               Entities, DTOs, application errors, and contracts
internal/adapter/     Service implementations and PostgreSQL adapters
pkg/                  Logging, token, and response helpers
migrations/           Versioned SQL migrations
```

The user feature demonstrates handler → service → repository → database. Each
service/repository call receives the request context. Extend these small
interfaces with the methods your application actually needs. Domain interfaces
use domain types and do not expose Gin or GORM. The example entity contains GORM
column tags for the sample PostgreSQL mapping.

## Configuration

Existing process environment values take precedence over `.env`. Missing `.env`
files are allowed; malformed files fail startup. Set `ENV=production` in the
process environment to skip `.env` loading. Defaults are shown in `.env.example`.

| Variable | Default | Purpose |
| --- | --- | --- |
| `ENV` | `development` | `development` or `production` |
| `PORT` | `8000` | HTTP port, 1–65535 |
| `DATABASE_URL` | Required | PostgreSQL URL |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, or `error` |
| `CORS_ORIGINS` | `*` | Comma-separated HTTP origins |
| `CORS_CREDENTIALS` | `false` | Requires explicit origins when enabled |
| `HTTP_READ_HEADER_TIMEOUT` | `5s` | Time to read request headers |
| `HTTP_READ_TIMEOUT` | `15s` | Time to read a request, including its body |
| `HTTP_WRITE_TIMEOUT` | `15s` | Response write deadline; must exceed request timeout |
| `HTTP_IDLE_TIMEOUT` | `60s` | Keep-alive idle timeout |
| `HTTP_REQUEST_TIMEOUT` | `10s` | Context deadline propagated to services/database |
| `HTTP_MAX_BODY_BYTES` | `1048576` | Maximum request body size |
| `SHUTDOWN_TIMEOUT` | `5s` | Graceful shutdown deadline |
| `READINESS_TIMEOUT` | `1s` | Database readiness check deadline |
| `DB_CONNECT_TIMEOUT` | `5s` | Initial database connection deadline |
| `DB_MAX_OPEN_CONNS` | `10` | Database pool maximum connections |
| `DB_MAX_IDLE_CONNS` | `5` | Pool idle connections; must not exceed maximum |
| `DB_CONN_MAX_LIFETIME` | `30m` | Maximum connection lifetime |
| `DB_CONN_MAX_IDLE_TIME` | `5m` | Maximum connection idle time |

Request context deadlines rely on downstream operations honoring cancellation;
they do not forcibly stop arbitrary handler code. Adjust HTTP write timeouts for
streaming endpoints. Reverse proxy trust is disabled by default; configure trusted
proxies explicitly if deploying behind one.

Logs are timestamped JSON on stdout with separate method, path, status, latency,
and request ID fields. Responses include `X-Request-ID`; valid UUIDs from an
upstream `X-Request-ID` header are preserved. Other values are replaced. Error
responses include the same ID for correlation.

SIGINT and SIGTERM trigger graceful HTTP shutdown, followed by closing the
connection pool. Startup failures exit nonzero. Deploy the binary produced by
`make build` (`./bin/server`) so signals reach the application process directly.

## Migrations and tests

```sh
make migrate-create NAME=add_email
# Fill in both generated SQL files.
make migrate-up
make migrate-down # Roll back one migration.
make check        # Formatting, vet, race tests, and build.
```

Migrations run separately from startup. GORM does not auto-migrate.
See [migrations/README.md](migrations/README.md).

Unit tests run without PostgreSQL. Integration tests create and delete a randomly
named schema inside the database supplied through `TEST_DATABASE_URL`; they do not
modify other schemas. Use a dedicated test database with schema-creation privileges:

```sh
export TEST_DATABASE_URL='postgres://postgres:postgres@localhost:5432/hexgogen_test?sslmode=disable'
make integration
```

Create `hexgogen_test` first. CI provisions PostgreSQL and runs repository, HTTP
user-flow, cancellation, and migration up/down/reapply tests. Token tests cover
valid, expired, malformed, tampered, and incorrectly keyed tokens. The token helper
is available for application-specific authentication; it is not wired into the
public example routes.
